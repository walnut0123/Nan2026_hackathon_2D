## 1. UnityShotPatterns 에셋 검토 + 보스 원형 탄막 패턴(패턴 5) 이식

### 요청
`Assets/UnityShotPatterns-master` 폴더의 탄막 에셋들을 전부 확인하고, 적용 가능하면 그중
하나를 기존 보스 캐릭터에 패턴으로 등록해 탄막 기능이 실제로 작동하는지 검증해달라는 요청.

### 진행
- `UnityShotPatterns-master`는 통째로 별도 Unity 프로젝트(자체 ProjectSettings/Packages
  포함)라 패키지처럼 임포트는 불가능하지만, 스크립트 자체는 의존성 없는 순수 MonoBehaviour라
  코드 이식은 가능함을 확인
- `CircleShot`(360도 원형 탄막), `HeartShot`, `ShapeShot`, `SpinShot`, `TargetGotoShot` 등
  6종 검토 후, 가장 고전적이고 검증이 쉬운 `CircleShot`을 선택
- `BossAttackController.cs`에 **패턴 5: 탄막(원형 투사체) 공격**을 기존 4개 패턴(일직선/광역기
  장판/낙하형 장판/정사각형 투사체)과 동일한 중첩 클래스 구조로 추가
  - 예고 링(경고 원)이 커졌다가 24발의 투사체가 360도 균등 분산 발사
  - 에셋의 껍데기 총알 대신 기존 `RangedProjectile`(Health/Hurtbox 연동 이미 완비)을 재사용
  - `RangedProjectile.Initialize`에 `overrideSpeed` 파라미터 추가(선택적) — 패턴별로 프리팹
    기본 속도와 다른 속도를 쓸 수 있게
- `Boss_PixelSwordsman`에 `Projectile_Ranged_Temp` 프리팹 연결

### 검증
Play 모드에서 코루틴을 리플렉션으로 직접 구동해 24발이 15도 간격으로 정확히 퍼지고,
damage/speed가 설정값과 일치함을 확인.

## 2. 탄막 패턴 세부 조정 (1차)

### 요청
1. 탄막 알갱이(투사체) 프리팹을 Inspector에서 수정 가능하게
2. 투사체 속도 감소
3. 해당 패턴은 예고(경고) 인디케이터 없이 진행 — 단, 기능 삭제가 아니라 **끄는 옵션**으로

### 진행
- `bulletPrefab`은 이미 public 필드라 Inspector 노출 상태였음(추가 조치 불필요)
- 속도 값 확인 질문 후("탄막 개수 24 vs 속도 어느 쪽?") 사용자 답변에 따라 **투사체 속도
  5 → 3.5**로 조정
- `CircleBulletPattern`에 `showWarmupIndicator`(기본 `false`) 필드 추가 — 예고 원 생성/갱신/
  파괴 코드를 조건부로 감싸 시각 효과만 끄고, 예열 대기 시간 자체는 유지(발사 타이밍 불변)

## 3. 보스 잡몹 소환 패턴 구현

### 요청
보스가 방 안 여러 지점에 종을 소환, 공중에 떠 있는 상태 유지, 플레이어 쪽으로 느리게 추적,
일정 주기로 탄막 발사, 파괴 가능, 보스가 종의 위치로 순간이동. 이어서 "마인 유닛 추적 + 주기
공격 시스템" 구현.

### 확인 질문 → 사용자 답변으로 범위 확정
- 비주얼: 절차적 도형이 아니라 **`3_Ink_A`**(사용자가 미리 만들어둔 오브젝트) 사용 요청 →
  실제로는 이번 세션에서 만든 전투용 `1_Ink_A`(Enemies 폴더, Health/Collider 보유)를 가리킨
  것으로 확인
- 순간이동 기능: **완전 삭제**(불필요), 공중부양도 삭제
- "마인 유닛" = 방금 만든 종(1_Ink_A)과 **완전히 동일한 개체** — 별도 유닛 아님

### 진행
1_Ink_A 프리팹의 기존 문제(3D `BoxCollider`, 태그 `Untagged`, `Health` 없음)를 먼저 발견해
- `BoxCollider2D`로 교체(크기/오프셋 유지), 태그 `Enemy`, `Health`(HP 10, 카드 3방 기준 —
  기존 트래시몹 CardSoldier/LongSoldier와 동일 기준) 추가

`BossAttackController.cs`에 **패턴 6: 잡몹 소환 공격** 추가
- 보스→타겟 방향을 "전방"으로 삼은 부채꼴(60°) + 최소/최대 거리 범위 안에 5마리 소환
- 탄막 발사 로직을 `FireCircleBulletBurst(pattern, 위치)`로 분리해 재사용 — 소환된 잡몹이
  죽으면 그 자리에서 패턴 5(탄막)가 그대로 재생됨(보스 본체 쿨타임과 무관)
- 다른 4개 패턴 비활성화, 탄막+소환 패턴 2개만 활성화하도록 씬 설정 변경

### 검증
Play 모드에서 5마리 소환 위치가 각도(±30°)/거리(1.5~4) 범위를 정확히 지키는지, 사망 콜백
구독과 탄막 재사용 로직이 정확한 위치에서 작동하는지 확인.

## 4. 몬스터 스폰 텔레그래프 VFX (1차 — "바닥 링 → 플래시 → 등장" 3단계)

## 7. 소환 VFX 전면 확산 + 마인 유닛 전투 시스템 대폭 확장

### 요청 (6개 작업)
1. 기존 소환 VFX를 모든 적 프리팹(+마인 유닛)에 연결
2. 마인 유닛 이동: 무한 추적 → **2초 이동 / 3초 정지 반복 사이클**로 변경
3. 마인 유닛에 근접 공격 추가(근접 유닛과 동일 판정 거리 도달 시 공격 모드 전환, 기존 탄막 실행)
4. 근접 공격(A)과 주기 공격(B)이 **하나의 공유 쿨타임**을 쓰도록 통합(동시 발동 방지)
5. 자폭 타이머 사망 연출: 체력 0 → 즉시 사망 대신 **자폭 타이머(빨간 VFX) → 최후 탄막 → 사망**
   순서로, 플레이어 피격 연출(`PlayerHitFlash`)과 유사한 형태로. 타이머 시작 시점부터 이동 중지
6. 마인 유닛에도 기존 적 체력바 시스템(`EnemyHealthBar`) 부여

### 진행
- `MonsterSpawnSequencer` 6개 프리팹 전부에 연결(`Enemy_CardSoldier`는 기연결 확인)
- `MobLinearChaser`에 2초 이동/3초 정지 사이클 로직 추가(정지 중엔 위치 갱신 자체를 안 함)
- `MobPeriodicBulletRing`을 재설계: attackRange 필드 추가, 근접 판정 거리에 "새로 진입하는
  순간"(엣지 트리거) 즉시 발동 + 주기 발동이 하나의 `attackCooldown`을 공유하도록 통합,
  외부에서 강제 발동 가능한 `public FireBurst()` 노출
- `MineSelfDestructSequence.cs` 신규 — `Health.OnDeath` 가로채 이동/공격 즉시 정지 → 빨간색
  깜빡임(PlayerHitFlash와 동일 기법) → `FireBurst()`로 최후 탄막 → `Destroy`. `Health.
  deathDestroyDelay`를 5초로 늘려 시퀀스가 끝나기 전에 강제 파괴되지 않게 함
- `1_Ink_A`에 `EnemyHealthBar` 추가(barSprite는 기존 CardSoldier와 동일 GUID 재사용)

### 검증
Play 모드에서 2초/3초 사이클 전환 및 정지 중 이동거리 0, 근접 진입 즉시 발동+재진입 시
재발동 안 함, 사망 즉시 정지+빨간색 적용, 최후 탄막이 실제로 플레이어에게 명중(콘솔 로그)
후 정상 파괴까지 전부 확인.

## 8. 예고 연출 락온 브라켓 교체 + 등장 강화

  `custom_Target` 스프라이트(medieval UI 번들, 4개 모서리 브라켓이 안쪽으로 좁혀지는 형태)

- `SpawnLockOnTelegraph.cs` 신규(+ 프리팹) — 같은 스프라이트/머티리얼을 재사용하되, 플레이어
  UX용 `TargetLockVFX.cs`는 건드리지 않고 별도 스크립트로 분리(타이밍이 달라서 원본 UX에

  2단계로 전환

  15% 구간 유지 후 서서히 복귀, 등장 순간 지면에서 퍼지는 **충격파 링** 추가(새 프리팹 없이
  기존 `flashBurstPrefab`을 재사용하되 스프라이트만 `BossIndicatorUtil.GetRingCircleSprite()`
  로 교체)
- 6개 프리팹 전부 재배선

### 검증
Play 모드에서 브라켓 스케일(3.5→1.0)/회전(60°) 궤적과 완료 콜백, 충격파 링이 실제 링
스프라이트+지정 색상으로 생성됨을 확인.

## 9. 세부 조정 4건

### 요청
1. 락온 브라켓 시작 스케일 축소(사용자가 이미 3.5→1.2로 직접 수정, **조금 더** 축소 필요)
2. 프리팹화되지 않아 콜라이더가 누락된 맵 오브젝트(`1_box_a`, `1_table`, `1_ink_a`,
   `1_ink_b`)에 `BoxCollider2D` 추가
3. map3 Vase가 적/보스 공격에도 파괴되는 문제 — **플레이어 공격에만** 파괴되도록 제한
4. Vase 카드 드롭 수량을 **항상 정확히 1장**으로 고정

### 진행
1. `telegraphStartScale` 1.2 → **1.1**
2. 씬 조사 결과 지정된 4종 외에 **중복 배치본**(`1_Box_A (1)`, `1_Table (1)/(2)/(3)`)도 같은
   문제가 있어 총 8개 오브젝트 전부에 `BoxCollider2D` 추가(Unity가 스프라이트 바운드
   0.5×0.5에 자동으로 맞춤)
3. 원인 진단: `RangedProjectile.cs`(몬스터/보스 원거리 공격이 공유하는 투사체)가 `"Enemy"`
   태그만 제외하고 `"Breakable"`은 제외하지 않고 있었음(`BossAttackController`/`BossOrbHit`은
   이미 제외 중이었는데 이 파일만 누락) → `Breakable` 제외 추가
4. 원인 진단: `BreakableDropper.cs`가 카드 52장을 각각 5% 독립 확률로 굴리는 `LootTable.
   GetDrops()`를 사용 중이라 평균 약 2.6장(0~다수 랜덤)이 나오고 있었음 → 이미 존재하던
   `LootTable.GetSingleDrop()`(가중치 비례 1개 선택, 몬스터 처치 드랍용으로 이미 있던 메서드)
   으로 교체 + 개수를 명시적으로 1로 강제

### 검증
Play 모드에서 브라켓 시작 배율 1.1 확인, 몬스터 투사체가 화병에 999 데미지를 시도해도 체력
불변 확인, 화병 파괴 10회 반복 테스트 전부 정확히 카드 1장만 드롭됨을 확인.

   가까우면 최대 20회 재추첨. 부채꼴 60°→80°, 최소거리 1.5→1.8, 최대거리 4→5로 확장.
   `mobCount` 5 → **3**

   `Enemy_LongSoldier`×2(원거리) + `Enemy_CardSoldier`×1(일반) + `1_Ink_A`×1(마인). 스폰

   `BoxCollider`(Physics2D가 완전히 무시)였음 → `BoxCollider2D`로 교체(크기/오프셋 유지) +

   책임 컴포넌트) 부착
