# 2026-07-30 작업 정리

카드 데미지 시스템 v5.0 설계서 검토부터 시작해서, 인벤토리 구조 리팩터링·신규 UI 2종·버그 수정·
몬스터 드랍/스폰 시스템 변경까지 하루에 걸쳐 진행한 전체 작업 기록.

---

## 1. 카드 데미지 시스템 개편 (v2.2 → v4.0)

### 1-1. 공식: 곱연산 → 덧셈+곱연산 혼합

기존(v2.2): `데미지 = 카드 액면가 × 족보 배율`
변경(v3.0~): `데미지 = (레벨 데미지 + 액면가 보너스 + 카드 강화) × 구성 배율 × 스테이지 계수`

- **레벨 데미지**: `2.0 + (레벨-1) × 1.6`. 카드를 **2회 획득할 때마다 레벨 +1**
  (`CardInventory.PlayerLevel`, `CardInventory.TotalAcquired` 기반).
- **액면가 보너스**: `(액면가-2) × 0.5`. 2~A(14) 13랭크가 어떤 배율에서도 안 겹치도록 0.5 등간격.
- **카드 강화**: 이미 보유한 카드를 또 주우면 그 슬롯만 `upgradeLevel +1`.

### 1-2. 구성 배율 전면 교체 (v4.0) — 3장/4장 시너지 복원

원래 있던 9단계 `PokerHandRank`(하이카드~스트레이트플러시, 5장을 다 채워야 스트레이트/플러시
인정)를 폐기하고, **같은 숫자 / 같은 무늬 / 연속 숫자를 독립 트랙으로 판정**하는
`CompositionType`으로 전면 교체:

| 구성 | 배율 |
|---|---:|
| 같은 숫자 2장 | ×1.25 |
| 같은 숫자 3장 | ×1.55 |
| 같은 숫자 4장(포카드) | ×2.30 |
| 투페어 | ×1.45 |
| 풀하우스 | ×2.10 |
| 같은 무늬 3장 | ×1.15 |
| 같은 무늬 4장 | ×1.60 |
| 같은 무늬 5장(플러시) | ×2.60 |
| 연속 3장 | ×1.20 |
| 연속 4장 | ×1.65 |
| 연속 5장(스트레이트) | ×2.45 |

배율은 확률(희귀도) 순이 아니라 **"몇 칸이 구속되는가"** 순으로 매김 — 같은 숫자 4장은 4칸만
구속(5번째 칸 자유)이라 가장 쉬우므로 가장 싸게, 같은 무늬 5장은 5칸 전부+무늬 제약까지라 가장
비싸게. 이렇게 안 하면 "같은 숫자만 모으기"가 지배 전략이 됨(원본 설계서 실측: 포카드를
최고배율로 두자 200판 중 108판이 그 루트로 수렴).

### 1-3. 인벤토리 자동교체

5칸이 다른 카드로 꽉 찼을 때 새 카드를 주우면 **가장 약한 슬롯을 자동으로 교체**
(`CardInventory.FindWeakestSlot` — 액면가 보너스+강화 수치 최소인 칸). 더 이상 "인벤토리가
가득 차 못 주움" 상태가 없음.

### 1-4. 발사 방식

기본은 **랜덤 투척**(매 발 보유 슬롯 중 무작위 1장). `CardInventory.useSequentialFire` 토글로
슬롯 순서대로 도는 완전 결정론 순차 발사로 전환 가능(디버그/재현용).

### 1-5. 밸런싱 도구

`CardInventory` 컴포넌트 우클릭 → 컨텍스트 메뉴:
- **Debug: 카드 상태 리포트** — 현재 구성·평균 데미지·권장 적 HP를 콘솔에 출력.
- **Debug: 랜덤 투척 편차 시뮬레이션** — 5발 누적 편차(변동계수)를 콘솔에 출력.

### 1-6. 적 HP 재산정

새 공식 기준으로 5개 적 프리팹 HP 재조정 (기준: Lv1·액면가 8 카드 데미지 5.0 가정,
일반 2발/정예 6발/보스 40발):

| 프리팹 | 티어 | 기존 | 변경 |
|---|---|---:|---:|
| Enemy_CardSoldier, Enemy_LongSoldier | 일반 | 9.6 | 10 |
| Enemy_Jack | 정예 | 24 | 30 |
| Enemy_Mushroom, Enemy_Ghost | 보스 | 90 / 100 | 200 |

### 1-7. 미구현으로 남긴 것 (의도적 스코프 아웃)

- **그림 카드 특수효과**(J 관통/Q 유도/K 폭발/A 방어무시) — `FaceEffect` enum과 매핑 함수만
  존재, 실제 투사체 관통·유도·스플래시 로직과 적 방어력 스탯은 없음.
- **CardInstance 구조체 전면 교체** — 원본 설계서는 `ItemData` 없이 무늬+숫자+강화를 값 타입
  구조체 하나로 관리했지만, 이미 만들어진 52장 에셋·UI·세이브 연동을 지키기 위해 기존
  `ItemData` 기반 구조를 유지하기로 결정.
- **카드 드랍 3장 중 1택 UI** — 백엔드(`CardDamageSystem.PreviewOffer`/`PreviewOffers`)만 존재.
  `Docs/TODO_카드_3선택_드랍_UI.md`에 설계 질문 정리해둠.

## 2. 인벤토리 내부 구조 리팩터링

`CardInventory.cs`에서 `ItemData[] slots`와 `int[] upgradeLevels` 두 개의 병렬 배열을
`CardSlot[] slots`(구조체 하나에 카드 참조+강화 수치를 같이 묶음) 하나로 통합. 외부에 노출되는
`Slots`/`UpgradeLevels` 프로퍼티는 얇은 뷰 어댑터(`ItemView`/`UpgradeView`)로 감싸서 계약은
그대로 유지 — `CardProjectile`, `CardAutoAttack`, `CardDamageSystem`, 세이브 시스템, UI 등
다른 파일은 전혀 안 건드림. 슬롯 하나의 두 값이 항상 같은 인덱스를 가리키도록 묶어서, 나중에
슬롯별 필드가 하나 더 늘어나도 병렬 배열 동기화 실수가 안 생기게 함.

세이브 시스템(`SaveData.cs`/`GameManager.cs`)도 슬롯별 강화 수치와 총 획득 횟수(플레이어 레벨의
근거)를 저장/복원하도록 확장(구버전 세이브도 안전하게 로드됨).

## 3. 신규 UI 2종

### 3-1. 카드 획득 팝업 (`CardAcquiredPopup.cs`)

화면 중앙에 카드를 주웠을 때 잠깐 떴다 사라지는 팝업. 카드 아이콘 + 이름 + 효과 설명 +
(시너지가 새로 발동했을 때만) 시너지 줄. 인벤토리가 꽉 차 자동교체가 일어나면
`대체 추천 카드: {밀려난 카드} > {새 카드}` 형식으로 표시.

### 3-2. 데미지 비교 디버그 패널 (`CardDamagePreviewDebugUI.cs`)

카드를 주운 직후 인벤토리 5칸의 "줍기 전 > 줍은 후" 데미지를 잠깐 텍스트로 보여주는 디버그
전용 패널. 처음엔 "근처에 주울 카드가 있을 때" 폴링하는 방식으로 만들었으나, 아래 4절의 즉시
자동 획득 도입으로 그 "대기 상태" 자체가 없어져서 실제 획득 시점에 스냅샷을 찍어 넘겨주는
이벤트 방식(`ShowSnapshot`)으로 다시 설계함 — 팝업과 같은 타이밍에, 같은 정보 소스로 뜬다.

### 3-3. 두 UI 작업 중 잡은 실제 버그

1. **월드스페이스 Canvas 재부모화(reparent) 스케일 버그** — 이 Canvas는 자체 스케일이
   0.0133(≈1/75)인 월드스페이스 캔버스라, MCP로 새 UI 오브젝트를 만들면 "월드 위치 보존"
   재부모화 로직 때문에 로컬 스케일이 75배로 튀는 현상이 매번 재발함. 생성 직후 항상 수동으로
   로컬 스케일=1, Z위치=0으로 보정해야 했음.
2. **자기 자신을 비활성화하면 Update()가 다시 안 도는 함정** — `CardDamagePreviewDebugUI`가
   스스로 `SetActive(false)`로 꺼버리면 Unity가 비활성 GameObject의 `Update()`를 더 이상 안
   불러서 영원히 다시 켜질 기회가 없어짐. 배경 Image와 텍스트 자식만 껐다 켜는 방식으로 수정.
3. **`StartCoroutine`이 비활성 오브젝트에서 조용히 실패** — `CardAcquiredPopup`도 같은 종류의
   함정에 걸려서, `SetActive(true)`를 코루틴 시작 "전에" 동기적으로 호출하도록 순서를 바꿈.

## 4. 버그 수정 — 날아가는 카드가 줍기 프롬프트를 잘못 띄우던 문제

**원인**: `InteractionDetector.OnTriggerEnter2D`가 `IInteractable`만 확인하고
`ItemPickup.isFieldDrop`(필드 드랍인지 여부 — 원래 카드 투사체를 걸러내려고 만들어둔 플래그)은
확인하지 않았음. 던진 카드 프리팹도 필드 드랍과 같은 프리팹을 재사용하다 보니 그대로 감지됨.

**수정**: `ItemPickup.IsFieldDrop` 공개 프로퍼티 추가 + `InteractionDetector`에서 카드인데
필드 드랍이 아니면 무시하도록 필터. 실제 물리 트리거로 검증(던진 카드는 걸러지고, 실제 필드
드랍 카드는 정상 감지됨을 확인).

이 수정을 하는 김에 **카드는 "줍기" 버튼을 기다리지 않고 범위에 들어오는 즉시 자동으로
줍도록** 함께 변경(사용자 요청) — `InteractionDetector.OnTriggerEnter2D`에서 필드 드랍 카드는
`interactablesInRange`에 넣지 않고 바로 `Interact()`를 호출. 무기 등 카드가 아닌 아이템은
기존처럼 프롬프트+버튼 흐름 유지.

## 5. 몬스터 드랍/스폰 시스템 변경

### 5-1. 몬스터당 아이템 1개만 드랍

기존 `LootTable.GetDrops()`는 52장 카드 각각 독립 확률(전부 5%)로 굴려서 평균 2.6개가 동시에
떨어지는 구조였음. `LootTable.GetSingleDrop()` 신규 — 기존 `dropChance` 값을 독립 확률이
아니라 **상대 가중치**로 재해석해서 정확히 1개만 뽑음(전부 5%로 동일하니 사실상 52장 중
균등 랜덤 1장과 동일). `MonsterDropper.SpawnDrops()`가 이 메서드를 쓰도록 교체.

### 5-2. 드랍 위치: 죽은 자리에 정확히, offset 없음

`dropOffset`(-2.5, 2)과 `scatterRadius` 랜덤 오프셋 필드를 제거하고 `transform.position`에
그대로 생성. `popForce`(위로 살짝 튀는 물리 임펄스)는 유지 — 위치 오프셋이 아니라 스폰 후
순수 물리 효과라 "정확히 죽은 자리에 생성"과 무관.

### 5-3. 몬스터 리스폰 7초

`MonsterSpawnEntry.respawnDelay` 기본값 3f→7f로 변경. `Main.unity`의 `MapManager` 오브젝트에
이미 저장돼 있던 스폰 항목 2개(Jack, LongSoldier)도 3.0→7.0으로 직접 수정.

## 6. GUI 기본값 설정 (디자인 편집용)

카드 획득 팝업/디버그 비교 패널 둘 다 **샘플 데이터(스페이드 에이스 기준)가 채워진 상태**를
기본값으로 저장해뒀고, 두 창의 **루트 GameObject는 기본적으로 비활성화**되어 있음:

| GUI | 하이어라키 경로 |
|---|---|
| 카드 획득 팝업 | `InGameCanvas / CardAcquiredPopup` |
| 데미지 비교 디버그 패널 | `InGameCanvas / CardDamagePreviewDebug` |

인스펙터에서 체크박스만 켜면 샘플 상태가 바로 보여서 이미지/텍스트/레이아웃을 편집하기 쉬움.
런타임(실제 플레이)에는 카드를 처음 획득하는 순간 코드가 알아서 찾아서 켜주므로 정상 작동함
(`Show()`/`ShowSnapshot()` 진입점에서 `Instance`가 비어 있으면 `FindObjectOfType(true)`로
찾아서 활성화하도록 구현). **주의**: 디자인 편집 후 다시 꺼서 저장할 것 — 켜진 채로 저장하면
게임 시작부터 화면에 계속 떠 있게 됨.
