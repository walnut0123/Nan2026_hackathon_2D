# 2026-08-08 작업 정리 — 맵4 보스 배치, 방 클리어 외곽선 버그 수정, 웨이브 시스템+난이도 밸런싱, 신규 몬스터 4종 제작

슬라임(1_Ink_A) 축소와 맵4 보스 배치에서 시작해, 방 클리어 시 나오는 외곽선 이펙트의 실제
렌더링 버그를 찾아 수정하고, 방 2·3·4의 웨이브 시스템/난이도 밸런싱/개발 테스트 스킵 기능을
새로 만들고, 마지막으로 맵1·2·3용으로 새로 디자인된 몬스터 스프라이트 4종(1-1/2-1/2-2/3-3)을
전부 프리팹화해서 실제 각 맵 로스터에 교체 배치하기까지 하루 동안 이어진 전체 작업 기록.
요청이 들어온 순서 그대로 정리한다.

## 1. 슬라임 프리팹 축소 + 맵4 보스 개체 배치

### 요청
- 슬라임 개체 프리팹 크기를 기존 대비 0.5배로 축소
- `Sprites/Enemy/Boss` 폴더에 업로드된 `Boss_idle`로 맵4에 보스 배치, 맵4의 기존 다른 몬스터
  소환 시스템은 끄기
- 맵3 보스에 들어있던 모든 기능(공격 패턴 등)을 동일하게 넣어서 맵4에 배치, 보스 소환 위치는
  Transform으로 직접 조정 가능하게
- 맵3 보스는 기존 기능은 모두 유지하되 체력만 15로 설정

### 확인 질문 → 답변
"슬라임 프리팹"을 찾을 수 없어 확인 → 실제로는 **`1_Ink_A`**를 가리킨 것으로 확인(이름을
잘못 말한 것).

### 진행
- `1_Ink_A.prefab` 루트 Transform `localScale`을 1→**0.5**로 축소
- `Boss_idle.png`가 960×192(5프레임) 스프라이트시트임을 확인 → 슬라이스 후 프레임 0을 정적
  idle 스프라이트로 사용(맵3 보스도 애니메이터 없이 정적 스프라이트만 쓰는 것과 동일한 방식)
- `Boss_PixelSwordsman`(맵3 보스)를 복제해 **`Boss_Map4`** 생성 — `BossAttackController`의
  모든 패턴 설정/`Health`/`CircleCollider2D`를 동일하게 복제, 스프라이트만 `Boss_idle`로 교체
  하고 새 스프라이트의 픽셀 크기 기준으로 스케일(0.234375)을 재계산해 기존 보스와 시각적
  크기를 맞춤
- 맵4 룸 중심 위치에 배치(일반 Transform이라 Inspector에서 자유롭게 재배치 가능), 맵4
  `Spawner`의 `RoomMonsterSpawner.preplacedEnemies`에 `Boss_Map4` 등록, 기존
  `spawnEntries`(다른 몬스터 소환 목록)는 비움
- 맵3 보스 `Health.maxHealth`를 100→**15**로 변경, 그 외 모든 설정은 그대로 유지. 신규
  `Boss_Map4`는 요청 범위 밖이라 체력 100 그대로 둠

### 검증
컴포넌트 값을 재조회해 두 보스의 `BossAttackController` 설정이 완전히 동일한지, 맵4 스포너의
`preplacedEnemies`/`spawnEntries` 상태가 의도대로인지 확인 후 씬 저장.

## 2. 방 클리어 외곽선 이펙트 점검 및 버그 수정

### 요청
방 클리어 시 나오는 외곽선 이펙트가 정상 작동하는지 점검, 모든 오브젝트에서 외곽선이 전체적
으로 균일하게 빠지는 부분 없이 작동하는지 확인.

### 진행
- `BreakableOutlineOnRoomClear`가 붙은 오브젝트 조사 → 맵3의 상자 3개 + 화병 4개뿐(맵1/2/4는
  Breakable 오브젝트 자체가 없어 해당 없음)
- 플레이모드에서 `SetOutlineVisible(true)`를 직접 호출해 강제로 켠 뒤 스크린샷으로 확인 →
  **상자류는 외곽선이 모서리 4점만 찍히고 몸체 윤곽선은 거의 안 보이는 심각한 버그**를 발견,
  화병도 바닥 쪽 일부가 끊겨 보임
- 원인 규명 과정: 텍스처 압축(DXT) 문제인지 의심해 비압축(RGBA32)으로 바꿔 재현했으나
  동일 증상 → 기각. `sprite.uv`를 직접 코드로 조회해 실제 원인 확정: **Unity의 Full Rect
  스프라이트 메시는 `Sprite Extrude` 설정과 무관하게 정의된 크롭 rect를 그대로 UV로 사용**
  (여백이 전혀 늘어나지 않음) — 상자/화병 아트가 자기 크롭 사각형 가장자리에 거의 딱 붙어있어
  외곽선 셰이더가 그릴 여유 투명 픽셀이 크롭 안에 없었던 것이 근본 원인
- `heart_queen.png` 아틀라스에서 `Box_A_closed`/`Box_B_closed`/`Box_C_closed`/`Vase_typeA`/
  `Vase_typeB` 5개 스프라이트의 크롭 rect를 안전 여백만큼 확장(상자 +2px, 화병 +1px, 인접
  스프라이트와 겹치지 않는지 픽셀 단위로 사전 확인) + pivot을 같이 보정해 씬 상의 시각적
  위치/앵커는 그대로 유지

### 검증
수정 후 플레이모드 스크린샷으로 상자 3개+화병 4개 전부 외곽선이 끊김 없이 완전한 윤곽으로
나오는 것을 확인.

## 3. 방 2·3·4 난이도 밸런싱 + 웨이브 시스템 + 개발 테스트 스킵 기능

### 요청
1. 방 2/3/4 각각의 유닛 체력·공격 요소를 조정해 방을 진행할수록 점진적으로 어려워지도록
   밸런싱
2. 한 방에서 유닛이 한 번에 다 나오는 게 아니라, 소울나이트처럼 방 안에서도 웨이브가 나뉘는
   형식 채택
3. 개발 테스트용: 각 방에서 몬스터 1마리·체력 1로 설정해 즉시 클리어 가능한 기능 추가, 방
   단위로 개별 on/off 가능하게(예: 방4 테스트하고 싶으면 방2·3만 체크), 보스방(4)은 이
   기능이 필요 없으므로 on/off 자체가 불필요

### 확인 질문 → 답변
- 웨이브 시스템 적용 범위: 보스방(4)에도 적용할지 vs 일반 몬스터방(2,3)에만 적용할지 →
  **방 2,3만 적용**(보스방은 기존처럼 단일 보스 전투 유지)
- 방별 웨이브 수/난이도 곡선 → **방2·3 둘 다 2웨이브, 대신 방3의 마릿수를 더 많게**

### 진행
- `RoomMonsterSpawner.cs`를 웨이브 구조(`List<RoomWave>`, 각 웨이브는
  `List<RoomSpawnEntry>`)로 재작성 — 한 웨이브가 전멸하면 다음 웨이브가 자동으로 이어서
  스폰. 기존 `preplacedEnemies`(보스 등 사전배치 개체) 로직은 그대로 유지해 웨이브와 함께
  동작
- `Health.cs`에 `SetMaxHealthAndFullHeal(float)` 메서드 신규 추가(최대체력을 바꾸고 그만큼
  풀피 회복 — 개발 테스트용 체력1 몬스터에 사용)
- `RoomMonsterSpawner`에 `devTestMode`/`devTestEnemyPrefab`/`devTestSpawnPoint` 필드 추가 —
  켜면 웨이브/사전배치를 전부 무시하고 지정 프리팹 1마리를 체력 1로 스폰, 처치 즉시 방 클리어
- **방2**: 2웨이브(1웨이브: LongSoldier+CardSoldier / 2웨이브: LongSoldier+슬라임), 기존
  스탯 그대로(밸런싱 기준점 역할)
- **방3**: 강화 변종 프리팹 3종 신규 제작(`Enemy_Jack_R3`/`Enemy_LongSoldier_R3`/
  `Enemy_CardSoldier_R3` — 체력 +50%, 공격력 2배). 1웨이브는 기존 3마리(Jack+LongSoldier+
  CardSoldier) 그대로 두고, 2웨이브에 강화 변종 2마리를 신규 스폰포인트 2개와 함께 추가 →
  총 그루트 5마리 + 기존 엘리트 보스(`Boss_PixelSwordsman`, 1절에서 체력 15로 설정됨)로
  방2(4마리)보다 확실히 많고 세게 구성
- **방4**: 웨이브 없음(기존처럼 보스만 사전배치 상태 유지), `devTestMode` 설정하지 않음
- 방2/3에는 `devTestMode`용 프리팹/스폰포인트만 미리 연결해두고 토글 자체는 꺼둔 채로 저장
  (필요할 때 Inspector 체크박스 하나만 켜면 바로 동작)

### 검증
플레이모드에서 스크립트로 직접 `SpawnAll()` 호출 → 웨이브1 스폰 확인 → 적 처치 →
웨이브2 자동 스폰 확인 → 전멸 시 `OnAllMonstersDefeated` 이벤트 발생까지 체인 전체 확인.
`devTestMode`도 별도로 체력1 몬스터 1마리 스폰 + 처치 즉시 클리어까지 확인.

## 4. 신규 몬스터 스프라이트 프리팹화 + 맵별 몬스터 교체 + 공격 타입 구현

### 요청
1. `Sprites/Enemy` 폴더에 업로드된 신규 디자인 몬스터(맵1용 1-1, 맵2용 2-1/2-2, 맵3용 3-3)
   스프라이트를 실제 몬스터 프리팹으로 제작
2. 각 맵에 소환되는 몬스터를 신규 제작한 몬스터로 교체, 전체 웨이브를 채우기엔 종류가
   부족하므로 동일 몬스터 중복 소환 허용
3. 몬스터별 공격 타입 구체 스펙
   - **1-1**(원거리): 기존 맵3 롱솔져와 시스템 거의 동일, 총기 등 추가 무기 없이 본체 입에서
     직접 총알 발사, 1회 공격 시 2발 발사
   - **2-1**(원거리): 1-1과 유사하나 탄환 알고리즘이 다름 — 플레이어 방향 기준 ±30도 부채꼴
     범위 내 랜덤 방향으로 발사
   - **2-2**(원거리): 1-1과 거의 동일한 방식, 1회 공격 시 4발 발사
   - **3-3**(돌진형): 보스 패턴과 유사하게 공격 전 인디케이터 표시(일직선 패턴과 동일한
     형태) 후 그 방향으로 돌진. 이 유닛들이 쓰는 탄막은 전부 `Sprites/Enemy/Bullet.png` 사용

### 진행
- 12개 스프라이트시트(1-1/2-1/2-2/3-3 각각 idle·run(또는 idle_run 통합)·atk·death)를 프레임
  단위로 슬라이스, `Bullet.png`는 단일 스프라이트로 임포트 설정
- 각 몬스터의 Idle/Run(또는 IdleRun 공용)/Attack/Die 애니메이션 클립 + 애니메이터 컨트롤러
  4세트를 코드로 직접 빌드 — 기존 `LongSoldier`/`Slime` 컨트롤러의 상태 구조를 그대로 재현
  (Idle↔Run은 Speed 임계값 트랜지션, AnyState→Attack(트리거)→Idle, AnyState→Die(트리거))해서
  기존 `EnemyAnimator`/공격 스크립트가 수정 없이 그대로 동작하도록 함
- **`RangedBurstAttacker.cs`** 신규 — `shotsPerBurst`(연사 수)/`spreadAngle`(부채꼴 각도)을
  Inspector 값으로 노출해 스크립트 복제 없이 1-1(2발 직선)/2-1(1발, ±30도 무작위)/2-2(4발
  직선)를 전부 이 스크립트 하나로 커버
- **`DashChargeAttacker.cs`** 신규 — `BossAttackController`의 일직선 패턴(`LinePattern`)과
  동일한 방식(`BossIndicatorUtil` 사각형 인디케이터 재사용, 예열 후 즉발 라인 데미지)에 실제
  돌진 이동을 추가해 3-3의 텔레그래프+몸통박치기 구현
- `MonsterSpawnSequencer`가 신규 공격 스크립트 2종도 인식하도록 mover/attacker 조회 체인 확장
- **`Projectile_MopBullet.prefab`** 신규(기존 `Projectile_Ranged_Temp` 복제, 스프라이트만
  `Bullet.png`로 교체) — 1-1/2-1/2-2의 탄막이 전부 이 프리팹을 사용
- 기존 `Enemy_LongSoldier` 프리팹을 템플릿으로 신규 프리팹 4개 제작
  (`Enemy_1-1_Mop`/`Enemy_2-1_Mop`/`Enemy_2-2_Mop`/`Enemy_3-3_Mop`) — 무기 전용 자식
  오브젝트(총 스프라이트)는 제거(요청대로 "추가 무기 없이 본체에서 발사"), 공격
  스크립트/스프라이트/애니메이터/콜라이더 반지름/체력을 몬스터별로 개별 설정
- 맵별 로스터 교체
  - **맵1**: 몬스터 스포너 자체가 없던 방(튜토리얼 성격의 시작 방)이라 `RoomMonsterSpawner`
    신규 추가 + 스폰포인트 2개 신규 배치 + `RoomController.monsterSpawner` 연결, 1웨이브·
    1-1 mop 2마리로 구성
  - **맵2**: 기존 로스터(LongSoldier×2+CardSoldier+슬라임)를 2-1/2-2 mop으로 완전 교체
    (2웨이브, 웨이브당 2-1 1마리+2-2 1마리)
  - **맵3**: 기존 로스터(+3절에서 만든 강화 변종 포함)를 3-3 mop 5마리로 완전 교체
    (2웨이브: 1웨이브 3마리/2웨이브 2마리, 기존 스폰포인트+3절에서 만든 신규 스폰포인트
    재사용), 엘리트 보스(`Boss_PixelSwordsman`)는 그대로 유지
  - **맵4**: 몬스터 웨이브가 없는 방이라 변경 없음

### 검증
플레이모드에서 4종 프리팹을 플레이어 근처에 직접 스폰해 전투가 에러 없이 진행(피격/사망/
카드드랍)되는지 확인. 맵1은 실제 게임 흐름 그대로 테스트 — "방 잠김 → 몬스터 출현 →
플레이어 자동공격으로 처치 → 방 클리어 → 문 개방"까지 콘솔 로그로 전체 파이프라인 확인.

## 6. 남은 작업 / 확인 필요 사항

- 맵1 신규 스폰포인트 좌표는 스크린샷으로 대략 확인한 추정 위치라, 실제 아트 보면서 미세
  조정이 필요할 수 있음.
- `devTestMode`는 방2·3만 프리팹/스폰포인트를 미리 연결해두고 꺼진 상태로 저장했음. 방1·4는
  설정하지 않음(방1은 요청 범위 밖, 방4는 명시적으로 불필요하다고 함).
- 신규 몬스터 4종(1-1/2-1/2-2/3-3)과 방3 강화 변종 3종(Jack_R3 등)의 체력/데미지/쿨타임/
  사거리 수치는 첫 배치 기준값이라, 실제 플레이테스트 후 밸런스 조정이 필요할 수 있음.
- 외곽선 버그를 수정한 5개 스프라이트(Box_A/B/C_closed, Vase_typeA/B) 외에 `Box_A/B/C_opened`
  등 미사용 상태이거나 외곽선 대상이 아닌 스프라이트는 손대지 않았음 — 추후 같은 아틀라스의
  다른 스프라이트를 외곽선 대상으로 새로 쓰게 되면 동일한 크롭 여백 문제가 재발할 수 있으니
  주의.
