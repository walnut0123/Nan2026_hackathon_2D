# 2026-08-01 작업 정리 — 보스 공격 패턴 (일직선 / 장판형 / 낙하형)

`Pixel character_with sword` 프리팹(임시 보스 캐릭터)에 텔레그래프(붉은 경고 인디케이터) 기반
보스 공격 패턴 3종을 구현하고, 패턴 간 동시 시전 방지 및 인디케이터 모양 수정까지 포함한
전체 작업 기록. 2026-07-31 ~ 2026-08-01 이틀에 걸쳐 진행.

## 1. 개요

- 대상 프리팹: `Assets/Prefabs/Enemies/Pixel character_with sword.prefab`
  (기존엔 `Transform`+`SpriteRenderer`만 있는 빈 껍데기 — 이 작업으로 첫 보스 패턴을 얹음)
- 씬 배치: `Main.unity`에 `Boss_PixelSwordsman` 인스턴스 1개, `Dummy_Scarecrow`(0,2,0) 우측
  `(2.5, 2, 0)`에 배치
- 공통 원칙: 모든 패턴은 **인디케이터(경고 표시) → 일정 시간 대기(예열/차징) → 실제 공격**
  순서로 진행되며, 텔레그래프가 보여준 자리/방향 그대로 공격이 나가야 플레이어가 보고 피할 수

  않음
- 각 패턴은 완전히 독립된 컴포넌트(공유 상태 머신 없음)로, 개별적으로 켜고 끄며
  (`enablePattern`) 따로 디벨롭할 수 있도록 설계

## 2. 보스 공격 패턴 3종

### 2-1. 일직선 공격 — `BossLineAttack.cs`

보스 위치에서 타겟(플레이어) 방향으로 붉은 직사각형 인디케이터가 사거리 끝까지 서서히
뻗어나가며 진해지고(예열), 예열이 끝나면 그 방향 그대로 실제 투사체(`BossLineProjectile.cs`,
신규)가 발사됨.

- 방향은 시전 시작 시점 타겟 위치로 고정
- 투사체는 `RangedProjectile`과 동일한 규칙(단일 명중 후 파괴, `Enemy` 태그 대상 제외)이지만
  이동 속도를 `Initialize(...)` 인자로 받아 패턴별 `projectileSpeed` 값을 그대로 반영

### 2-2. 장판형 공격 (자기 중심) — `BossAoeAttack.cs`

**보스 자신의 현재 위치**를 중심으로, 작은 원(차징 표시)이 큰 원(실제 피격 범위)에 닿을 때까지
서서히 커지다가 맞닿는 순간 큰 원 범위 전체에 한 번에 데미지.

> 중심을 "보스 자신"으로 둔 것은 요청사항에 명시가 없어 임의로 정한 기본값 — 필요하면
> 언제든 타겟 위치 기준으로 바꿀 수 있음.

### 2-3. 낙하형 장판 공격 (플레이어 주변 랜덤) — `BossMeteorAttack.cs`

"하늘에서 떨어지는" 느낌의 장판. 텔레그래프/데미지 로직은 2-2와 완전히 동일하지만, 중심점만
**시전 시점 플레이어 위치를 기준으로 `targetRandomRadius` 반경 내의 무작위 지점**으로 정해짐
(역시 시전 시작 시점에 한 번 고정).

두 장판 패턴은 로직이 거의 동일하지만, "각 패턴을 독립적으로 디벨롭할 수 있어야 한다"는
설계 원칙에 따라 공유 베이스 클래스 없이 별도 스크립트로 분리함.

## 3. 패턴 간 동시 시전 방지 — `BossAttackState.cs`

초기 버전은 각 패턴이 자기 쿨타임만 독립적으로 관리해서, 여러 패턴이 동시에 튀어나오는 순간이
있었음. 이를 막기 위해 보스 하나당 공유되는 잠금 컴포넌트를 추가:

- `IsBusy` / `TryBeginCast()` / `EndCast()` 세 가지만 있는 단순한 컴포넌트
- 프리팹에 수동으로 붙일 필요 없음 — 각 패턴 스크립트의 `Awake()`에서
  `GetComponent<BossAttackState>() ?? AddComponent<BossAttackState>()`로 알아서 공유 인스턴스
  하나를 찾거나 붙임
- 각 패턴은 캐스팅 시작 직전 `TryBeginCast()`로 선점을 시도하고, 실패하면(다른 패턴이 이미
  시전 중) 그 프레임은 넘어감. 캐스팅이 끝나면 `EndCast()`로 반납
- 정확히 하나의 `BossAttackState`가 세 패턴에 공유되는 것과, 실제로 한 패턴이 시전 중일 때
  다른 패턴의 선점 시도가 막히는 것까지 Play 모드에서 확인 완료(4절 참고)

---

## 4. 인디케이터 절차적 생성 — `BossIndicatorUtil.cs`

프로젝트에 원형 스프라이트 에셋이 전혀 없어서(정사각형 `WhitePixel.png` 하나뿐), 인디케이터용
스프라이트를 런타임에 코드로 직접 생성해서 정적으로 캐싱하는 유틸리티:

| 메서드 | 용도 |
|---|---|
| `GetRectangleSprite()` | 왼쪽 피벗 사각형 — 일직선 공격 인디케이터/투사체 |
| `GetFilledCircleSprite()` | 꽉 찬 원 — 장판형 큰 원(피격 범위 전체)/작은 원(차징) |
| `GetRingCircleSprite()` | 테두리만 있는 원 — 현재 사용처 없음(추후 아웃라인 스타일이 필요할 때 대비해 남겨둠) |

외부 아트 의존성이 없고, 인디케이터/투사체 GameObject는 보스의 부모가 아닌 **독립 오브젝트**로
생성됨(보스 프리팹 자체 스케일이 0.12로 매우 작아서, 자식으로 붙이면 인디케이터도 같이
축소되는 문제를 피하기 위함).

---

## 5. 버그 수정 — 큰 원이 "띠"처럼 보이던 문제

처음 구현 시 장판형 공격의 "큰 원(실제 피격 범위)"에 `GetRingCircleSprite()`(테두리만 있는
원)를 잘못 사용해서, 전체 범위가 아니라 얇은 띠 모양으로만 보이는 문제가 있었음.
`GetFilledCircleSprite()`로 교체해서 전체 영역이 다 위협 범위임을 보여주도록 수정
(`BossAoeAttack`/`BossMeteorAttack` 둘 다 적용). 꽉 찬 원으로 바뀌면서 기존 테두리 기준
알파값(0.5)이 너무 진해 보여서 기본값을 0.3으로 낮춤.

## 7. 검증

이 환경 특성상(에디터가 OS 포커스를 못 가져서 Play 모드 프레임이 거의 안 돎) 실시간 대기 대신
Play 모드 진입 후 `execute_code`로 private 메서드를 리플렉션 직접 호출하는 방식으로 검증:

- `BossLineAttack.targetTransform`이 `PriorityTarget`(`Dummy_Scarecrow`)로 정상 해석됨
- `CreateIndicator`/`FireProjectile` 정상 동작, 발사된 투사체가 허수아비 콜라이더와 충돌 시
  `Health.OnDamaged` 정상 발화(데미지량 일치)
- `BossAoeAttack.DealDamage`가 보스 위치 기준 `OverlapCircleAll`로 사거리 내 허수아비를 정상
  타격
- 세 패턴 모두 동일한 `BossAttackState` 인스턴스를 공유하는 것 확인(참조 동일성)
- 상호 배제 테스트 중 실제로 한 패턴이 이미 자동 시전 중인 상태를 우연히 포착 —
  그 상태에서 다른 두 패턴의 `TryBeginCast()` 시도가 정확히 실패하고, `EndCast()` 직후 바로
  성공하는 것까지 확인(단순 잠금 오브젝트 단독 테스트보다 신뢰도 높은 실제 경로 검증)
- `BossMeteorAttack.targetTransform`도 정상 해석, 큰 원 인디케이터가 `GetFilledCircleSprite()`
  를 사용하는 것 확인
- 컴파일 에러 0건, 콘솔 에러 0건

**미검증**: 인디케이터가 자라나며 점점 빨개지는 애니메이션과 쿨타임→시전 주기가 실제 화면에서
어떻게 보이는지는 위 환경 제약으로 육안 확인 못 함 — 실제 포커스된 상태로 플레이할 때 한 번
확인 권장. (사용자가 직접 Play 모드로 테스트한 뒤 문제없다고 확인한 바 있음.)

## 9. 남은 작업 / 확인 필요 사항

- **장판형(자기 중심) 공격의 중심점**이 "보스 자신 위치"로 되어 있음 — 요청사항에 명시가
  없어 임의로 정한 기본값. 타겟(플레이어) 위치 기준으로 바꾸고 싶다면 요청 필요.
- 보스 캐릭터 자체는 여전히 `Health`/`EnemyChaser`/충돌체/태그가 없는 상태 — 공격 패턴만
  구현된 상태이고, 데미지를 받거나 플레이어를 쫓아오는 기능은 아직 없음(요청 범위 밖이라
  손대지 않음).
- 인디케이터 예열 애니메이션의 실제 화면 느낌은 위 7절대로 육안 최종 확인 권장.
- `GetRingCircleSprite()`는 현재 아무 데서도 안 쓰임 — 추후 아웃라인 스타일 인디케이터가
  필요해지면 재사용 가능.

# (이어서) Room 클리어 시스템 완성 / 미니맵 / 환경 프리팹 / 버그 수정 모음

같은 날 이어서 진행한 두 번째 작업 묶음. Room 클리어 시스템(방A/B/C, 문, 몬스터 스폰, 보상)을
실제 플레이 가능한 수준까지 완성하고, 미니맵을 새로 만들고, 그 과정에서 발견된 버그를
다수 수정한 전체 기록. 대부분의 검증은 이 환경(에디터가 OS 포커스를 못 가져 Play 모드 프레임이
거의 안 도는 문제)의 제약 때문에 `execute_code`로 private 메서드/이벤트를 리플렉션으로 직접
발동시켜 검증했고, 매번 테스트 후 씬 상태를 원상복구(Idle, 문 잠금 해제, 스폰된 클론 삭제,
보스 재비활성화 등)한 뒤 저장했다.

## 1. Room B(전투방) 씬 구성 완료

방 4요소(벽/바닥/문/몬스터 스포너) 배치, `RoomController`에 문·스포너·보상 참조 연결까지
마무리. 몬스터 2마리(Enemy_LongSoldier, Enemy_CardSoldier)가 방 잠김 시 스폰되고 전부 죽으면
클리어 → 문 개방까지 리플렉션으로 전체 사이클 검증.

**버그 발견 및 수정**: `RoomRewardActivator.Activate()`가 `objectsToActivate` 배열을 인스펙터에서
비워두면(null) `NullReferenceException`으로 죽는 문제 발견 — null 가드 추가.

## 2. 미니맵 시스템 신규 제작 (뷰포트 패닝 방식)

기존에 있던 "방마다 작은 사각형 아이콘 하나씩" 추상 격자 미니맵을 폐기하고, 사용자 요청대로
전면 재설계:

- `MinimapPanel`(UI 슬롯)에 `RectMask2D`를 씌워 뷰포트로 만들고, 그 안에 `MinimapContent`(전체
  지도 컨테이너)를 배치
- `MinimapContent` 안에 방/복도를 대충 그린 회색 사각형들(방A/복도/방B/복도/방C, 실제 월드
  배치 비율 8px/유닛로 축소)과 마리오 스프라이트 `PlayerIcon` 배치
- `MinimapController.cs`: 방과 미니맵 사각형을 매칭한 목록을 들고 있다가, 해당 방의
  `OnPlayerEnteredRoom` 이벤트가 오면 아이콘을 그 방 위치로 옮기고
  `content.anchoredPosition = -방위치`로 패닝해서 그 방이 뷰포트 정중앙에 오도록 함(추후 전체
  지도 확대 기능을 위해 `content`만 스케일하면 되는 구조)

**버그 발견 및 수정**: `RoomController.NotifyPlayerEntered()`가 "최초 입장 시에만"
`OnPlayerEnteredRoom`을 발동하도록 잠금 판정과 한 몸으로 묶여 있어서, 방을 나갔다 재입장해도
미니맵이 갱신 안 되는 문제 발견 — 이벤트 발동을 잠금 판정보다 앞으로 옮겨서 재입장 때도 항상
발동하도록 분리(잠금/스폰 판정 자체는 여전히 최초 입장으로만 게이팅).

## 3. Room A(당시 "입구방", 보스방 아님) 최초 구축

기존 방 이미지(`test_0` 스프라이트, world x:-5~5·y:-3.52~3.52) 경계에 맞춰 벽 5개로 감싸고,
보스(`Boss_PixelSwordsman`, 이미 씬에 배치돼 있던 오브젝트)를 죽이면 클리어되도록
`RoomMonsterSpawner`를 확장:

- `preplacedEnemies` 리스트 신규 — Instantiate하지 않고 씬에 이미 있는 오브젝트를 그대로 두되
  죽음만 추적하는 방식(기존 `spawnEntries`는 프리팹 Instantiate 방식이라 보스처럼 손으로
  꾸며둔 오브젝트엔 안 맞음)
- `RoomController.lockOnStart` 플래그 신규 — 시작 방은 Bounds 트리거로 감지 불가능(플레이어가
  트리거 밖에서 안으로 들어오는 게 아니라 처음부터 안에 있으므로)하니 `Start()`에서 직접
  `NotifyPlayerEntered()` 호출

## 4. BoxCollider2D size=0 버그 (MCP 환경 이슈) — 전수 재점검

Unity-MCP `manage_components add`로 `BoxCollider2D`를 추가하면 에디터에서 직접 "Add Component"
할 때와 달리 기본 size가 `(1,1)`이 아니라 **`(0,0)`으로 생성**되는 걸 발견. Transform 스케일은
맞았지만 콜라이더 자체 크기가 0이라 물리적으로 존재하지 않는 것과 같아서, 방 벽/문/Bounds
트리거를 그동안 지나다녀도 아무 충돌도 안 일어나고 있었음. `Physics2D.Distance`로 직접
겹침 여부를 검증하며 이미 만들어둔 모든 벽/문/트리거 콜라이더의 size를 `(1,1)`로 명시
재설정. 이후 새로 만드는 모든 콜라이더는 생성 직후 항상 size를 명시하는 방식으로 대응.

## 9. 보스/몬스터 즉시 활성화 버그

방A에 있는데 방B의 보스가 게임 시작과 동시에 소환되는 문제 발견. 원인: 방 시스템은 보스의
"죽음 추적"만 담당했을 뿐, 보스 자체는 씬에 항상 **활성 상태**로 미리 배치돼 있어서
`BossAttackController`가 Play 시작과 동시에 그냥 작동 중이었음.

- `RoomMonsterSpawner.TrackEnemy()`에 `enemy.SetActive(true)` 추가 — 이제 preplaced 적은 씬에서
  **비활성 상태로 시작**하고 방이 잠기는 순간 코드로 켜짐
- `Boss_PixelSwordsman`을 씬에서 비활성화
- 부수 버그: `BossHealthBarUI`/`BossHealthTextUI`가 `FindObjectOfType<BossAttackController>()`로
  보스를 찾는데, 이 함수는 기본적으로 비활성 오브젝트를 못 찾음 — `includeInactive: true` 추가

같은 원인으로 **일반 몬스터(soldier/Jack)도 게임 시작 직후 등장**하는 문제도 함께 발견됨 —
알고 보니 방 시스템과 무관한 훨씬 이전부터 있던 별도의 무한 리스폰 파밍 스포너
(`MonsterSpawn.cs`, `MapManager` 오브젝트)가 5마리(Jack×2/LongSoldier×2/CardSoldier×1)를 게임
시작과 동시에 스폰 중이었음. 이 5마리를 방B의 `RoomMonsterSpawner.spawnEntries`로 옮기고
(기존 스폰 포인트 Transform 재사용), 레거시 `MonsterSpawn`의 목록은 비움. 이제 보스와 똑같이
방B 입장 판정 이후에만 등장.

`RoomController`에 `spawnDelay` 필드 신규(문이 잠긴 뒤 몬스터가 나타나기까지의 지연) — `LockRoom()`을
코루틴으로 전환해 문은 즉시 잠기고 몬스터는 지연 후 등장하도록 분리.

## 10. 방B 입구 판정 타이밍 — 2차 수정

**1차 리포트**: 방A를 나가자마자 보스가 소환됨 → 방B 전체를 덮던 큰 트리거(`Bounds_A`)를
삭제하고, 실제 입구 두 곳(남쪽 `Door_South` 방향, 동쪽 `Door_A` 방향)에 각각 작은
`EntranceTrigger_South`/`EntranceTrigger_East`를 신설해 문턱을 실제로 통과했을 때만 반응하도록
변경. 스폰 딜레이 1초 적용.

**2차 리포트**: 여전히 복도에 있는데 스폰됨 → `EntranceTrigger_South`가 사용자가 직접 수정해둔
방B 벽 경계(y≈-3.46~-3.06)에 거의 겹쳐 있어서 문턱만 스쳐도 반응하고 있었음. 방 안쪽으로
확실히 밀어넣음(y: -3.2→**-2.5**, 크기 확장). `Physics2D.Distance`로 방A 문~복도 전 구간~벽
두께 구간까지 전부 미반응, 방 안쪽(y=-2.5)에서만 반응함을 검증. 스폰 딜레이
1초→**2.5초**→(이후 요청으로)**1.5초**로 조정.

**3차 리포트(진짜 원인)**: 사용자가 직접 진단 — `RoomBoundsTrigger`가 플레이어 판정에
`GetComponentInParent<PlayerInventory>()`를 쓰는데, 이건 플레이어 밑의 **아무 콜라이더나**
닿아도 반응함. 방 트리거 위치가 아무리 정확해도, `InteractionTrigger`(상호작용 판정용, 발밑
콜라이더보다 큼)가 먼저 닿으면 그걸로 반응해버림. `RoomBoundsTrigger.cs`를
`other.GetComponent<PlayerInventory>()`(부모 탐색 없이 정확히 그 콜라이더의 오브젝트에서만
확인)로 수정 — `PlayerInventory`는 발밑 이동 콜라이더와 같은 오브젝트(Player 루트)에만 있고
`HurtBox`/`InteractionTrigger` 등 자식 콜라이더에는 없다는 점을 이용. 이후 `InteractionTrigger`
범위를 다시 넉넉하게(radius 0.27→**0.7**) 키움 — 이제 room 판정과 완전히 분리되어 상호작용
편의성만 고려해 조정 가능.

## 15. 보스 체력바 "0" 표기 버그 — `Health.cs` 지연 초기화

보스 체력바가 뜬 직후 잠깐 0/100으로 보였다가 첫 타격 이후에야 정상 표시되는 버그.

**원인**: `Health.currentHealth`는 `Awake()`에서만 `maxHealth`로 초기화되는데, 보스는(9절 참고)
방B 입장 전까지 비활성 상태라 `Awake()`가 안 돎. `RoomEntryActivator`가 방 입장 즉시 체력바를
켜면 `BossHealthBarUI.Start()`가 아직 초기화 안 된 `currentHealth`(C# 필드 기본값 0)를 읽어서
"0/100"으로 표시. 이후 보스가 실제 활성화돼도(Awake 실행돼 값은 바로잡힘) 아무도 체력바에
"다시 그려라" 신호를 안 주기 때문에, 실제로 때려서 `OnDamaged` 이벤트가 뜰 때까지 화면은 계속
0으로 고정.

**수정**: `Health.cs`에 지연 초기화 추가 — `CurrentHealth`를 처음 읽는 순간(Awake 실행 여부와
무관하게) `maxHealth`로 채워지도록 `EnsureInitialized()` 헬퍼 도입. 보스가 비활성 상태여도
체력바가 뜨는 즉시 정확한 값을 보여줌.

## 17. 남은 작업 / 확인 필요 사항

- **방C(그런트방)**: 방B와 달리 아직 spawnDelay/entrance trigger 정밀화가 적용 안 됨(방C는
  원래도 큰 문제 리포트가 없었음) — 필요하면 방B와 동일한 패턴 적용 가능.
- **보상 상자**: 현재 `Box_A_Closed` 하나만 방B 클리어에 연결됨. 방C 클리어 시 보상은 아직
  없음(요청 범위 밖).
- **Door_South 위치**: 기능상 문제는 없지만, 이름과 달리 실제로는 방A 출구(복도 남쪽 끝)에
  놓여 있어 방B가 잠길 때 봉인되는 지점이 방B 벽면이 아니라 복도 입구 쪽. 시각적으로
  "문이 방B 벽에 딱 붙어 잠기는" 느낌을 원하면 위치 이동 필요(현재는 그대로 둠).
- 방/복도 미니맵 아트는 여전히 회색 사각형 placeholder — 사용자가 별도로 실제 이미지 제작 예정.
